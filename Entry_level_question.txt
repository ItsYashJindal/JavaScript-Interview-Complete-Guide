4.  what is asynchronous/ synchronous ? 
->  In synchronous execution, JavaScript runs code line by line, and each operation must finish before the next
    one starts. If one task takes time, it blocks the main thread, and the remaining code has to wait until that task 
    is completed. This means the program cannot move forward until the current operation finishes.

->  In asynchronous execution, JavaScript does not block the main thread for time-consuming tasks. When an 
    asynchronous operation like a timer, API call, or Promise is triggered, JavaScript moves it to the background 
    using Web APIs and continues executing the remaining code. Once the asynchronous task is completed, its result is 
    handled later by the Event Loop.

5.  what is event loop ? 
->  Java script is single threaded but event loop allow us to handle async operation. event loop continuously 
    checks, Is the call stack empty or not ,If yes, move pending tasks to the call stack. first of step all 
    Synchronous code runs in the Call Stack, If the code is asynchronous, like setTimeout, Promise, or an API call, 
    it is sent to libuv. libuv handle the task in the background. After the task is completed, it does not go 
    back directly to the Call Stack. Instead, Promise->related tasks are sent to the Microtask Queue, and setTimeout 
    or DOM events are sent to the Callback (Macrotask) Queue. The Event Loop keeps checking if the Call Stack is 
    empty. When it is empty, the Event Loop first moves all tasks from the Microtask Queue to the Call Stack and 
    executes them. Only after that, it takes tasks from the Callback Queue and moves them to the Call Stack one by 
    one. This is how JavaScript manages asynchronous code even though it runs on a single thread.

6.  what is async await ? 
->  Async/await is used to handle asynchronous operations efficiently in JavaScript. It is used inside functions, 
    where the async keyword is used to create an async function, and an async function always returns a Promise. and The 
    await keyword pauses the execution of the async function until the Promise is resolved or rejected.

7.  what is promises ?
->  A Promise in javascript is a way, which show an asynchronous task is completed or not. A Promise has three 
    states: pending, fulfilled, and rejected. The pending state means the operation is still in progress, fulfilled 
    means the operation has completed, and rejected means the operation has failed. 

8.  what is map/ reduce/ filter ? 
->  Map, filter, and reduce are JavaScript array methods used to work with array data in an easy and clean way. 
    The map method is used when we want to perform an operation on every element of an array and return a new array 
    with updated values. The filter method is used when we want only specific elements from an array based on a 
    condition, for example getting all numbers greater than 4 from an array. The reduce method is used when we want 
    to combine all elements of an array into a single value, such as calculating the total, sum, or any final result 
    from the array data.

9.  what is hoisting ? 
->  Hoisting is a JavaScript behavior where variable and function declarations are processed before the code is 
    executed.However, only the declaration is hoisted, not the value. Function declarations are fully hoisted.

10. what is callback function ?

    after some work is completed. It is mainly used to handle asynchronous operations in JavaScript, such as API 
    calls. the callback function runs once the task finishes.

12. what is buffer and streams ?
->  When a file is received from a server, it usually comes in small pieces called chunks. These chunks are 
    temporarily stored in local memory before they are processed, and this temporary storage is called a buffer. When 
    the server sends data continuously in a sequence of chunks, that continuous flow of data is called a stream.

13. Why is Node.js preferred over other backend technologies like Java and PHP?
->  Node.js works well when you need to handle many requests without waiting on slow I/O. Its non-blocking model helps 
    with that. Another plus is that you can use JavaScript on both the client and the server, which keeps things simple.

    The npm ecosystem also makes it easy to pull in libraries and tools. That said, Node.js isn’t the best choice for 
    everything. For heavy CPU work, languages like Java or PHP can still be a better fit.

14. What are the pros and cons of Node.js?
->  Node.js offers fast execution, excellent scalability, and strong support for real-time applications. It uses JavaScript,
    which simplifies full-stack development, and has a mature ecosystem via npm.

    On the downside, Node.js is not ideal for CPU-heavy tasks unless worker threads are used, and poorly written asynchronous
    code can still become hard to maintain. by default node js is single threaded.

15. What are common security vulnerabilities in Node.js applications?
->  Node.js apps can face security issues, especially when handling user input, authentication, or API access. Most of these
    problems come from weak input checks, unsafe settings, or dependencies that haven’t been updated in a while.

    Some of the most common security issues include :-
    *) Cross-site scripting (XSS) 
    *) Cross-site request forgery (CSRF)
    *) SQL or NoSQL injection attacks
    *) Insecure JWT handling
    *) Improper CORS configuration
